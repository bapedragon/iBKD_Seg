# B0의 기존 실행 중단 설정과 소요시간 구분

**2026-09-25 정정:** 예상 소요시간은 실측 속도로 계산할 값이며 실행 제한과 다릅니다.
이전 응답에서 둘을 혼동해 9시간 40분을 코드 제한에 반영했습니다. 사용자 결정으로
예상 시간을 정하는 것처럼 안내한 설명을 정정합니다. 9시간 55분으로 새 제한을 설정하지 않았습니다.
현재 코드에 남아 있는 동작을 아래에 기록하며, 이를 실제 완료 예상 시간으로 사용하지 않습니다.
실측에 따른 이번 예상은 [10k 이슈](H200_TOP1_10K_ISSUE.md#예상-소요시간과-기존-중단-설정)에 있습니다.

2026-09-24 적용된 기존 코드의 실행 예산은 **9시간 40분(34,800초)**입니다.
운영 설정 ID는 `b0_job_runtime_9h40_v1`입니다. 설치·데이터 준비·학습·평가·저장을 포함하는
스크립트 실행 예산이며 서버의 10시간 한도까지 20분 여유를 둡니다.

적용 대상은 `run_b0_warmup20.py`의 smoke/2k/10k, 기존 `run_b0_screen2000.py`,
기존 7개 방법 `run_b0_smoke.py`와 새 `run_b0_top1_10k.py`입니다.
Top1 10k 묶음은 ALG·iBKD 두 실행이 하나의 9시간 40분 예산을 공유합니다. 변경된 코드로 새로 시작하거나 재개하는 작업부터 적용됩니다.
이미 실행 중인 작업에는 소급 적용되지 않습니다.

학습 runner는 기존 저장 절차를 유지해 9시간 40분 안에 마무리합니다.
Deadline은 시작 후 9시간 37분이며 worker는 그 90초 전부터 현재 update/평가를 마무리하고
checkpoint를 저장합니다. 대략 **9시간 35분 30초부터 정상 중단**을 시작하는 구조입니다.
새 후보를 시작할 시간 여유가 부족하면 해당 후보는 pending으로 남깁니다.
7개 방법의 짧은 smoke runner는 전체 9시간 40분 timeout을 사용합니다.

고정 프로토콜 JSON의 과거 `32400` 값은 기존 실행 식별과 checkpoint 호환성을 위해 보존합니다.
활성 시간 예산은 실행 요약의 **`job_runtime.maximum_job_seconds=34800`**에 별도로 기록합니다.
이 운영 설정은 학습 source/protocol signature에 추가하지 않으며, 같은 학습 조건의
기존 checkpoint 재개를 막지 않습니다. 학습 step 수, β·λ, guidance warm-up, LR schedule,
입력·평가 규칙은 바뀌지 않습니다.
