# Tiny · L/16 첫 step CE 비율에 맞춘 2,000step 후보 비교

2026-09-28 사용자 결정. **2026-09-29 사용자 로그에서 ALG 네 후보의 H200 실행 완료를 확인했습니다.**
2,000step·전체 val500·첫 step 비율 검사를 모두 통과했고, 준비 포함 **2시간 14분 14초**입니다.
[전체 결과와 확인 범위](results/alg_grid2000/RESULTS.md)에 기록했습니다.
Tiny의 mIoU 순위는 **3 → 1 → 4 → 2**, L은 **2 → 1 → 4 → 3**입니다.
새 10k 제안 후보는 **3번 β=0.08804125116886172**, **1번 β=0.01760824897930404**이며,
새 10k는 아직 실행하지 않았습니다. 기존 Tiny 8개 후보 탐색의 순위와 구분합니다.
목적은 L에서 성능이 좋았던 초기 guidance/CE 비율이 Tiny에서도 좋은지 확인하는 것입니다.
각 모델의 고정 2,000step 전체 val500 **mIoU 순위·1위·상위 2개**를 비교합니다.
완료한 첫 실행은 **ALG 후보 4개**이며 LG·iBKD나 10k를 자동으로 시작하지 않습니다.
[이전 Tiny 탐색 보존 기록](../../reports/legacy_tiny_beta_search/README.md)과 별도 실험입니다.
로컬 검사 38개와 셸 문법 검사를 통과했습니다. 작은 CPU 모듈을 사용한 공통 학습·중단/재개,
초기 비율 검사, 네 후보 순위 출력, 실패·동점·로그 잘림 처리를 확인한 사전 검사입니다.
H200 실측과 로그 검증은 위 결과 보고서에서 별도로 구분합니다.

## 후보 산출과 고정 조건

`목표 비율 = L의 β × L 첫 step guidance / L 첫 step CE`

`새 Tiny β = 목표 비율 × Tiny 첫 step CE / Tiny 첫 step guidance`

L의 **기존 2,000step 각 실행의 first_step 원시 수치**를 사용합니다. 이전 Tiny의 첫 batch
CE=3.79216, guidance=5.93974는 유효숫자 6자리 로그 기반이므로 계산한 β는 근삿값입니다.
매 실행 첫 batch에서 optimizer update 전에 목표와 실측 비율을 확인합니다.
허용오차는 상대 0.01%(rtol=0.0001), 절대 0.00000001이며, 벗어나면 해당 실행을 실패로
보고하고 β를 자동 변경하지 않습니다. 이 검사는 학습 중 비율을 고정하는 기능이 아닙니다.

| 새 후보 | L의 ALG β | 목표 첫 step CE 비율 | 새 Tiny β(표시 근사) | L 2k mIoU (%) | L 순위 |
|---|---:|---:|---:|---:|---:|
| alg_l16r1 | 0.02 | 2.758017% | 0.017608248979 | 53.608 | 2 |
| alg_l16r2 | 0.05 | 6.895043% | 0.044020622448 | 58.409 | 1 |
| alg_l16r3 | 0.10 | 13.790086% | 0.088041251169 | 19.876 | 4 |
| alg_l16r4 | 0.20 | 27.580171% | 0.176082489793 | 42.836 | 3 |

실제 β·비율은 [설정 JSON](../../configs/alg_l16_ratio_grid2000_v1.json)에 전체 정밀도로 고정합니다.
[alg_reference.json](alg_reference.json)에 L의 원시 요약 경로·SHA-256·CE·guidance·평가값,
Tiny 측정 근거와 산출식을 보존합니다. H200 실행은 Git의 이 참조 파일을 사용하므로 L 원시 파일을
서버에 별도로 올릴 필요가 없습니다. 원본 자료의 확인은 로컬 준비 단계에서 수행했습니다.

- 기존 Tiny와 동일한 OpenMMLab DeepLabV3-R101 teacher, Tiny/16·decoder1·fine train2975,
  seed1·crop512·batch8·FP32·SGD LR0.01·**80k poly LR schedule**을 유지합니다.
- ALG warm-up=0, smoothing window=50, threshold=−0.02를 유지합니다. 조건을 만족하면
  가장 이르게 745step부터 가이던스가 꺼질 수 있으며, 강제로 켜두거나 종료시키지 않습니다.
- 네 후보 모두 같은 초기 상태·입력 순서에서 **0→2,000step 새 학습**합니다. 이전 500/2k/10k
  checkpoint를 사용하지 않습니다. 새 실행이 시간 중단됐을 때만 같은 commit·설정으로 재개합니다.
- 별도 500step 선별을 거치지 않고 2k까지 진행합니다. 중간 로그로 초기 안정성을 확인하고,
  기존 Tiny처럼 NaN/Inf·실행 실패를 보고합니다. 유한한 loss 급증만으로 후보를 자동 제외하지 않습니다.
- 각 후보의 **고정 2,000step**에서 원본 해상도 전체 val500을 한 번 평가합니다.
  mIoU가 우선이며 accuracy·19 IoU를 함께 기록합니다. Test나 best checkpoint를 사용하지 않습니다.

## 실행과 예상 시간

아래 명령은 완료한 2k 실행을 재현하는 경로입니다. 같은 네 후보를 다시 돌릴 필요는 없습니다.

```bash
env -u CITYSCAPES_TI16_RESUME CITYSCAPES_TI16_START_RUN=1 bash phase4/Cityscapes_Segmenter-Ti16/scripts/run_alg_l16_ratio_grid2000.sh
```

이슈 제출은 사용자가 수행합니다. 여러 줄 명령이 누락된 이력이 있으므로 실행 명령 칸에는
실행 시점에 고정한 commit checkout과 위 명령을 한 줄로 전달합니다. 이 문서는 이슈 입력용 파일이 아닙니다.

기존 Tiny ALG 8개 실행에서 후보당 학습+전체 val은 **1,896.6~2,075.4초(31.6~34.6분)**,
평균 **1,995.4초(33.3분)**였습니다. 네 개는 약 **2시간 13분**, 이전 묶음의 준비·프로세스
오버헤드 약 9분 36초를 더하면 **약 2시간 23분**입니다.
실행 전 **약 2시간 15분~2시간 40분**, 여유 있게 3시간을 예상했고,
실제 준비 포함 **8,054.39초(2시간 14분 14초)**에 완료했습니다. 가이던스 종료와 서버 상태에 따라 달라집니다.
시간 예산은 기존대로 10시간, 시작 후 **9시간 58분 중단 요청·120초 저장 여유**입니다.

출력은 `/app/output/cityscapes_ti16_alg_l16_ratio_grid2000_v1/run_<UTC>_<PID>/`입니다.
`artifacts/grid_summary.json`과 후보별 `artifacts/alg_l16r1/`~`alg_l16r4/`를 보관합니다.
중간 로그를 유지하고 마지막 **`[CITYSCAPES_TI16_L16_RATIO2000_FINAL]`**에 네 후보의 β,
목표/실측 CE 비율, 완료/선택 step·epoch, loss·CE·guidance, mIoU·accuracy·19 IoU,
가이던스 종료 step, checkpoint 검사·경고·오류·시간·L/Tiny 순위를 함께 출력합니다.

## 해석 및 후속 후보 선정

- L의 기준 순위는 **2 → 1 → 4 → 3**입니다. L도 보관된 2k mIoU로 정렬합니다.
  후보 3의 ALG는 L에서 3epoch에 가이던스를 종료했으므로 LG와 합치지 않습니다.
- 네 후보가 모두 정상 완료되고 초기 비율도 맞아야 전체 순위·상위 2개·Spearman 순위 상관을
  제시합니다. 미완료 후보를 꼴찌로 취급하지 않고, 정확한 동점은 임의 순위를 만들지 않습니다.
- 새 10k 후보는 새 2k mIoU 상위 2개를 제안하되 자동 실행하지 않습니다. 이전 Tiny 8개 후보의
  상위 2개와 섞지 않습니다. 작은 차이는 seed 반복 전에는 견고한 순위로 단정하지 않습니다.
- 이는 초기 **scalar loss 비율을 맞춘 단일 seed 탐색**입니다. 모델별 gradient 영향이나 장기
  학습 순위까지 같다는 뜻은 아닙니다. L/Tiny 코드·연산·checkpoint 경로가 완전히 같은 실험으로
  주장하지 않습니다. 예를 들어 L은 data_workers=4, 현 Tiny는 0이며 이전 L에는 유한한 guidance
  급증 중단 규칙도 있었습니다. 완료 후보의 동일 학습량 mIoU 순위를 우선 비교합니다.
- 향후 iBKD도 λ0.25와 λ0.5를 각각 수행합니다. L에서는 β 후보를 그대로 두고 λ만 바꿔서
  두 λ의 초기 비율이 달랐습니다. 각 λ에서 L이 실제 사용한 비율을 따로 맞춥니다.
  L의 λ0.25·β0.1은 2k 평가가 없으므로 전체 네 후보 순위에는 추가 확인이 필요합니다.
